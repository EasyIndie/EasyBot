# API 生命周期与弃用

EasyBot 的公开 REST API 使用 `/api/v1` 版本前缀，完整 OpenAPI 契约由快照门禁保护。兼容性新增可以继续进入 v1；删除端点、重命名字段、收紧输入、改变类型或响应语义等破坏性变化必须使用新版本路径。

当前没有已弃用的 v1 操作，因此服务不加载弃用中间件。首次需要弃用时，必须先发布迁移文档和替代端点，再实现集中弃用策略。响应应使用：

- RFC 9745 `Deprecation: @<Unix秒>`；
- RFC 8594 `Sunset: <HTTP-date>`；
- `Link` 的 `deprecation` 与可选 `successor-version` 关系。

弃用不改变端点当下行为。正式客户至少获得一个已公告、可测试的迁移窗口；具体时长由合同和变更风险决定，但 Sunset 日期必须位于公告之后，且在窗口内保持旧端点安全可用。浏览器 CORS 会暴露这些响应头。到期删除旧端点仍属于破坏性契约变更，必须通过 OpenAPI 快照审阅、CHANGELOG、发布审批和客户通知，不能只删除策略表记录。
