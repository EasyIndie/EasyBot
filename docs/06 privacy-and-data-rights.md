# 隐私与数据主体请求操作手册

本文是 EasyBot 运营方的技术操作基线，不是可直接发布的法律文本。正式上线前，应由法律顾问结合经营主体、服务地区、客户类型和所接入平台审核隐私政策、服务条款、数据处理协议及跨境传输安排。

## EasyBot 处理的数据

EasyBot 可能保存聊天平台标识、聊天与用户标识、显示名称、消息正文、平台原始事件、机器人回复、出站投递请求与结果、人工对账证据、时间戳、会话元数据、API Key 哈希、用量指标和管理审计记录。运营方必须根据实际启用的平台和配置维护数据清单，不应仅依赖本列表。

## 数据导出

拥有 `sessionsread` 权限的受控操作员可以分页导出一个会话：

```http
GET /api/v1/sessions/{session_key}/export?limit=500&offset=0
Authorization: Bearer <authorized-key>
```

响应包含会话资料、消息正文、原始数据以及该平台聊天关联的出站投递请求、结果和人工对账证据。消息和投递记录分别分页：当 `truncated=true` 时继续传 `next_offset`，当 `deliveries_truncated=true` 时继续传 `next_delivery_offset`；两者都为 false 才表示该会话已完整导出。单类记录每页最多 1,000 条。`before` 可用于消息时间边界，但完整导出优先使用 offset，避免相同时间戳的消息跨页时被遗漏。导出期间应暂停该会话的新消息写入或在开始时固定时间边界。导出动作写入审计账本。导出文件本身属于敏感数据，应加密传输、设置短期有效期并在交付后删除。

## 级联删除

拥有 `sessionsmanage` 权限的受控操作员可以删除会话：

```http
DELETE /api/v1/sessions/{session_key}
Authorization: Bearer <authorized-key>
```

该操作删除该会话关联的全部消息正文、`raw_data` 和出站投递记录（包括请求正文、平台结果、对账证据和内部调用方 ID），再删除会话记录，并返回 `deleted_messages` 与 `deleted_deliveries`。即使会话索引已不存在，只要可从 `platform:chat_id` 会话键定位孤立数据也会继续删除。删除动作写入审计账本。消息 TTL 清理也使用同一消息保留期删除过期投递记录，避免新增数据表绕过保留政策。

删除只作用于 EasyBot 控制的在线数据库，不会撤回聊天平台上的消息，也不会立即抹除已生成的加密备份、外部日志、Prometheus 或客户自行保存的副本。运营方必须制定备份到期删除、日志脱敏以及下游处理者通知流程，并在对外政策中说明实际删除时限。

## 请求处理流程

1. 验证请求者身份及其对目标聊天账号的控制权，避免向冒充者泄露数据。
2. 记录请求编号、法律依据、范围、接收时间和法定期限；不要把身份证件直接写进审计元数据。
3. 确认是否存在依法必须保留的数据、争议冻结或安全调查；任何拒绝或延期应由合规负责人批准。
4. 使用最小权限、短期 API Key 执行导出或删除，并保存审计事件 ID。
5. 检查所有分页均已导出，或在线消息查询已为空；需要时通知 Webhook、日志、备份和其他处理者负责人。
6. 通过经过身份验证的渠道向请求者确认完成，并按内部政策关闭工单。

## 上线门禁

- 明确运营方是控制者、处理者还是二者兼有，并与商业客户签署相应协议；
- 为每个平台确认机器人授权范围、数据使用限制和删除能力；
- 配置消息及会话保留期，默认不应无限期保留；
- 明确数据驻留、跨境传输、子处理者和政府请求处理方式；
- 指定安全事件联系人、数据泄露评估和通知时限；
- 定期抽查导出完整性、级联删除、备份到期删除及审计链告警。
