# EasyBot G0 首发商用候选范围

> 候选版本：0.0.20
> 当前阶段：G0，冻结首个商用版本
> 更新日期：2026-07-30

本文只定义首个封闭付费试点前的承诺边界。它不是正式公网发布公告，也不替代 G1/G2/G3 所需的真实生产、法务、收款和客户证据。

## 候选服务形态

首发只提供独立托管实例：

- 每个客户一套 EasyBot 实例；
- 每个客户独立数据库、`auth.db`、密钥目录、备份批次和指标标签；
- 使用生产 Compose、固定镜像 digest、HTTPS 反向代理和生产启动门禁；
- 不在同一 EasyBot 进程内混放多个互不信任客户。

## 首个 SKU

建议首个 SKU 命名为 `Managed Pilot`，只用于 G3 封闭试点。

| 项目 | G0 默认值 | 说明 |
|---|---:|---|
| 部署形态 | 独立托管实例 | 单客户、单实例、独立数据 |
| API 请求额度 | 600 requests/min/customer | 通过 API Key `requests_per_minute` 执行 |
| API Key 数量 | 最多 100 个有效 Key | 轮换期间允许 1 个过渡 Key |
| 消息数据保留期 | 30 天 | 试点期可按客户合同缩短 |
| 备份频率 | 每日 1 次 | G1 需完成真实介质恢复演练 |
| 本地完整备份保留 | 至少 7 个完整批次 | 需配合异地对象存储策略 |
| 恢复目标 | RPO 24h，RTO 4h | G1 恢复演练后再写入合同 |
| 支持时段 | 工作日 10:00-18:00 Asia/Shanghai | G3 前不承诺 7x24 |
| 严重事件首次响应 | 4 小时内 | 仅限试点客户 |

以上数值是 G0 候选边界，不是正式 SLA。G1 容量、恢复和告警证据未通过前，不得写入公开销售页或正式合同。

## 首发平台边界

G0 不直接承诺所有适配器都可商用。进入 G3 前，每个平台必须用真实账号完成入站、出站、断连恢复、重试和幂等烟测。

| 平台 | G0 状态 | 承诺边界 |
|---|---|---|
| Telegram | 待 G1 真实账号烟测 | 通过后可纳入首批试点 |
| Discord | 待 G1 真实账号烟测 | 通过后可纳入首批试点 |
| 飞书 | 待 G1 真实租户烟测 | 需确认平台政策和 SDK 版本 |
| QQ | 待 G1 真实账号烟测 | 仅限已验证连接和恢复路径 |
| WeChat | 暂不默认纳入首发 | 需要单独验证账号、政策和消息链路 |

销售说明只能写“已在 G1 通过真实烟测的平台”。未通过的平台可作为内部试验能力，不作为付费承诺。

## 暂不支持清单

G3 退出前不建设或承诺：

- 进程内多租户隔离；
- 自助注册；
- 自动支付；
- 完整团队 RBAC；
- 插件市场；
- 不可信原生插件；
- 7x24 值守；
- 零数据丢失承诺；
- 跨区域高可用；
- 客户自助升级、回滚和迁移；
- 未经真实烟测的平台适配器。

## G0 冻结规则

候选版本冻结后，只接受：

- P0/P1 缺陷；
- 安全修复；
- G1 上线阻塞修复；
- 文档和证据路径更正；
- 验证脚本修复。

其他产品能力、平台扩展、UI 优化和自动化计费全部推迟到 G3 退出后重新评估。

## 退出证据

G0 完成时至少需要：

- `bash scripts/verify.sh --locked` 通过日志；
- `scripts/release-preflight.sh 0.0.20` 通过日志；
- `git diff --check` 通过日志；
- 候选 commit；
- 候选 tag；
- 不可变镜像 digest；
- 本文经过发布负责人确认。
